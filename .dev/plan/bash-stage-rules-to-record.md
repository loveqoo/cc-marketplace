# Bash 단계 규칙: 차단에서 기록으로 (설계, 2026-08-09)

사용자 결정의 기록이다. 코드는 이 문서에 합의한 뒤에 손댄다.

## 왜

`shell.py`(Bash 명령 해석)가 **19번 고쳐졌다.** 커밋 7개, 파일 안에 기록된
"전에 틀렸다" 17건, 그 위에 현장 보고 2회차의 2건.

원인은 부주의가 아니라 **설계가 정확한 답을 요구하기 때문**이다.

```
지금: 명령에서 정확한 경로를 알아낸다 → 규칙을 적용한다 → 막는다
```

막으려면 경로를 정확히 알아야 하고, 정확히 알려면 세상 모든 CLI 도구의 인자
규약을 알아야 한다. 이건 유한하지 않다 — 같은 도구도 플래그로 규약이 뒤집힌다.

| 명령 | 실제로 쓰는 곳 |
| --- | --- |
| `cp a b` | `b` (마지막) |
| `cp -t dir a b` | `dir` (첫째) |
| `sed -i s/x/y/ a b` | 둘 다 |
| `install -d x y` | 둘 다 |

**이 셋은 지금도 틀려 있다.** 즉 "동사 표를 정확히 만든다" 는 길은 이미 실패한
길이다. 그리고 반대 방향(오탐)도 같은 뿌리에서 나왔다 — `find -name '.git'`,
`git diff origin/main..HEAD`, `curl … > x` 의 `https:/`, `docker -t org/app:1.0`.
**한 줄의 추측에 반창고가 네 개 붙어 있다.**

들어내는 것도 시험했다. 단정 16개가 깨진다 — `touch src/a.py`,
`mkdir -p src/newdir` 같은 진짜 차단이 사라진다. **고칠 수도 지울 수도 없다.**

## 무엇을 바꾸나

바꾸는 것은 판정이 아니라 **판정의 등급**이다. 같은 추측이라도 결과를 무엇으로
쓰느냐에 따라 틀렸을 때의 대가가 다르다.

| 추측을 무엇으로 쓰나 | 틀렸을 때 대가 | 유지보수 |
| --- | --- | --- |
| 막는다 (지금) | 막다른 길 · 엉뚱한 사유 · 모델이 잘못 학습 | 영원히 |
| 묻는다 | 확인 한 번 | 줄지만 남음 |
| **기록만 한다** | **없음** | **끝난다** |

**틀려도 대가가 없으면 고칠 이유가 없어진다.** 추측 기계는 남아 있어도 무해해진다.

그리고 이건 새 설계가 아니다. 코드가 자기 입으로 이미 적어 두었다
(`shell.py`, `BASH_OPAQUE` 주석):

> 이것은 경계가 아니라 **가시성**이다. 경계는 바닥값과 래퍼 무결성이다.

단계 규칙은 원래부터 경계가 아니었는데 구현만 경계처럼 하고 있었다. **경계의
대가를 가시성의 값에 치르고 있었다.**

## 판정표 — 전후

| 무엇 | 지금 | 바뀐 뒤 |
| --- | --- | --- |
| 바닥값(엔진·DB·래퍼)을 특정 | deny | **deny 그대로** |
| 바닥값을 담은 폴더 / 원문에만 보임 / 해석 불가 | ask | **ask 그대로** |
| `find -delete`·`xargs rm` 처럼 대상이 실행 결과 안 | ask | **ask 그대로** |
| 하네스 제어 명령(skip·allow·loop new…) | 동의 게이트 | **그대로** |
| **Write/Edit 의 단계 규칙** | deny | **deny 그대로** |
| **Bash 의 단계 규칙** | deny | **기록만 (통과)** |

바꾸는 줄은 **마지막 하나**다.

### 남는 ask 의 사유가 바뀐다

`bash_opaque`·`bash_unresolved` 의 현재 메시지는 *"단계별 쓰기 규칙을 적용할
대상을 정할 수 없으므로"* 라고 말한다. 단계 규칙이 더 이상 막지 않으므로 이
사유는 거짓이 된다. 그 둘이 실제로 지키는 것은 **바닥값**이다
(`find . -name harness.db -delete` 는 토큰에 바닥값이 없어 어떤 문자열 검사도
지나간다). 메시지를 바닥값 기준으로 다시 쓴다.

## 정정 — 추측이 틀렸을 때의 대가는 0 이 아니다

처음 이 문서를 쓸 때 "기록만 하면 틀려도 대가가 없다"고 적었다. 코드를 보니
**완전한 말이 아니다.** 경로 추측은 차단 말고 두 곳을 더 먹인다.

- **재편집 계수(churn)** — 같은 파일을 몇 번 고쳤나. `metrics` 의 지표다
- **증거 판정** — `.dev/plan/**` 등에 쓰면 조건이 충족된 것으로 인정하는 경로

그래서 틀린 추측은 **계측기를 오염시킨다.** 결론은 바뀌지 않는다 — 오염된
계측은 "잘못 막힘"보다 훨씬 싼 대가다. 다만 다음 둘을 지킨다.

1. 기록 이벤트는 `block` 과 **다른 종류**로 남긴다 (마찰 추세 오염 방지)
2. 증거 판정(`write_glob`)에 쓰이는 경로는 **추측이 아니라 문법이 증명한 것만**
   쓴다 — 리다이렉트 대상. 추측으로 증거가 서면 안 된다

## 기록은 어떻게 남나

- 새 이벤트 종류 하나. `block` 과 섞지 않는다 — 섞으면 `metrics` 의 마찰 추세가
  **추측으로 오염된다.** 우리가 재려던 바로 그 숫자다.
- 문구는 **추측임을 드러낸다.** "바꿨다" 가 아니라 "바꾸는 것으로 **보인다**".
- `status` 와 `recall` 에서 보인다. 회차 종료 요약의 차단 수에는 넣지 않는다.
- 틀린 기록은 버그가 아니다(아래 끝 조건).

## 잃는 것 — 명시한다

**Selection 단계에서 `touch src/a.py` 를 쳐도 막히지 않는다.** 기록에는 남지만
실행된다. `sed -i`, `> src/a.py` 도 같다.

받아들이는 근거는 하네스가 스스로 선언한 상대다 — *"적대적인 모델을 막는 장치가
아니라 규칙을 지키려는 모델의 실수를 잡고 기록을 남기는 장치"*. 그런 모델은
파일을 고칠 때 Write/Edit 을 쓰고, 그 문은 도구가 경로를 그대로 주므로 **추측이
없고 지금까지 버그도 없었다.** Bash 로 소스를 고치는 것은 소수 경로다.

"Bash 로도 반드시 막혀야 한다"가 요구사항이면 이 설계는 틀렸다. 그때는 19번의
반복을 계속 받아들이는 것 말고 방법이 없다.

## 끝 조건

1. Bash 로 단계 규칙 밖에 쓰는 명령이 **통과하고, 기록이 남는다**
2. 바닥값 차단은 **하나도 약해지지 않는다** — 기존 바닥값 단정 전부 통과
3. Write/Edit 의 단계 규칙은 **그대로 막는다**
4. 현장 보고 1·2차의 오탐 4건이 전부 통과한다 (이미 통과하지만 회귀 방지로 유지)
5. `metrics` 의 마찰 추세에 추측 기록이 **섞이지 않는다**
6. 남는 `ask` 의 사유 문구가 바닥값 기준으로 정확하다

## 그리고 — 반복을 끝내는 규칙

이 변경의 값은 코드가 아니라 **이 한 줄**이다.

> **Bash 경로 추측이 틀렸다는 보고는 더 이상 버그가 아니다.**

기록이 지저분해질 뿐 아무도 막지 않으므로 고칠 이유가 없다. 이 문장을
`POLICY.md` 와 README 에 적는다. 적지 않으면 다음 보고 때 또 고치게 된다 —
지금까지 19번이 그랬다.

기존 반창고 넷(`:` 마디, `..` 마디, find 문법, 리다이렉트 대상)은 **지운다.**
기록의 정확도를 위해 남길 이유가 있어 보이지만, 남기면 "정확해야 한다"는 요구가
남고 그러면 다섯 번째가 붙는다. 기록은 틀려도 되는 것이어야 한다.

## 회차 밖 — 이번에 하지 않는 것

- **바닥값을 샌드박스에 위임** (`sandbox.filesystem.denyWrite`). **별도 회차로
  결정됨.** 이번은 빼는 일이고 저건 더하는 일이라, 섞으면 무엇이 무엇을 고쳤는지
  안 보인다. 근거와 출처는 `.dev/shell-write-detection-is-undecidable.md`.
- **2차 보고 §5** (새 기본 규칙이 기존 설치에 안 옴). 경고가 이미 발화 중이다.
- **1층(진짜 셸 파서)**. 이 설계가 서면 파싱 정확도의 값이 더 떨어진다.
- **하네스를 우리 저장소에 설치**. 별개 결정이고 이미 거절됐다.

## 지울 반창고 — 대상을 정확히 한다

처음 쓸 때 "반창고 넷" 이라고 뭉뚱그렸는데 하나는 **다른 층의 것**이다.

| 반창고 | 어디에 | 이번에 |
| --- | --- | --- |
| `:` 든 마디 제외 (`https:/`, `org/app:1.0`) | `_target` 추측 | **지운다** |
| `..` 든 마디 제외 (`origin/main..HEAD`) | `_target` 추측 | **지운다** |
| `find [경로] [식]` 문법 자르기 | `bash_writes` 추측 | **지운다** |
| 읽기 명령 + 리다이렉트 (`ls … 2>&1`) | **바닥값 판정** | **남긴다** — 바닥값은 계속 차단하므로 이 오탐은 계속 비싸다 |

넷째를 지우면 2차 보고 §1 이 그대로 되살아난다. 지울 것은 **추측 층의 셋**이다.
