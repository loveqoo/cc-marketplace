# 문법이 확정하는 것만 판정한다 (설계, 2026-08-12)

사용자 결정의 기록이다. 코드는 이 문서에 합의한 뒤에 손댄다.

> **정확한 것만 제한한다. 하지 못하는 것은 포기한다.**

## 왜 — 실측

도그푸딩 저장소의 실제 세션 기록에서 Bash 호출 589개를 꺼내 훅에 재생했다.
합성 코퍼스로는 증상이 재현되지 않아서, 진짜 기록을 썼다.

| 판 | 멈춤 | 비율 |
| --- | --- | --- |
| 0.73.0 | 126 / 589 | 21.4% |
| 0.74.0 (`expand` 제거) | 65 / 589 | 11.0% |

남은 65건의 정체:

| 규칙 | 건수 | 성격 |
| --- | --- | --- |
| 제어명령·승인 게이트 | 26 | **설계대로** — `harness` 명령, `allow`/`skip` |
| `parse-fail` | 20 | **우리 결함** — 따옴표 안에서 쪼개 조각이 깨짐 |
| `consent` | 9 | 설계대로 |
| `floor-deny` | 4 | 정확 (deny) |
| `floor_named` | 4 | 정확 |
| `containment` | 2 | 판단 필요 |

**실질 오탐은 `parse-fail` 20건이고, 원인은 하나다** — `BASH_SPLIT` 이 인용을
모른 채 `; & | 개행` 에서 쪼갠다. 명령 전체는 `shlex` 로 파싱된다(14/14 확인).
우리가 부순 것이다.

## 무엇을 쓰나 — 의존성 없이 된다

`shlex(punctuation_chars=True)` 는 **표준 라이브러리**이고, 인용을 알면서
연산자까지 토큰화한다. 다섯 케이스로 확인했다:

    grep -rln "ts-expect-error\|@ts-" tests/ | head   → 연산자 ['|']   (따옴표 안 \| 은 글자)
    node -e "console.log(a>1?'x':'y')"                 → 연산자 []      (?: 는 글자)
    find . -name "*.py" -exec echo {} \;               → 연산자 [';']
    SP=/private/tmp/x; cp index.js "$SP/head.js"       → 연산자 [';']

파서를 도입하는 것이 아니라 **이미 쓰는 것을 제대로 쓰는 것**이다. 이 플러그인이
표준 라이브러리만 쓰는 성질은 유지된다 — 훅으로 매 명령마다 도는 물건이다.

## 규칙 — 아는 것과 모르는 것을 가른다

지금 결함의 뿌리는 **그 구분이 없다는 것**이다. 모르는 것을 아는 척하거나
(`_/` 라는 없는 경로를 지어냈다), 아는 것까지 되물었다(`print(1+1)`).

새 규칙은 낱말 단위로 하나다.

| 낱말이 | 무엇을 아나 | 판정 |
| --- | --- | --- |
| **리터럴** (확장 없음) | 값을 정확히 안다 | 판정한다 |
| 같은 명령 안에서 **리터럴 대입된 변수** | 상수 전파로 값을 안다 | 판정한다 |
| `$HOME`·`$(pwd)`·바깥 변수 | 값을 모른다 | **포기 — 통과** |

그리고 자리 단위로 하나 더. **어느 인자가 대상인지 문법이 답하는 자리만** 쓴다.

| 자리가 | 판정 | 왜 |
| --- | --- | --- |
| **리다이렉트 대상** (`> f`, `>\| f`, `of=`) | 판정한다 | 문법이 쓰기임을 증명한다 |
| **`rm`·`shred`·`truncate` 의 인자** | 판정한다 | 이 명령들은 인자를 **전부** 지운다. 어느 것인지 물을 필요가 없다 |
| `cp`·`mv`·`ln`·`install`·`tee`·`sed -i` … | **포기** | 어느 인자가 대상인지 문법이 모른다 |

셋째 줄이 핵심이다. 예전에는 "변경 동사의 인자에 리터럴 바닥값이 있으면 판정"
이었는데, 그 규칙은 `cp .claude/harness/bin/harness /tmp/backup`(정당한 백업)도
막는다. `cp` 와 `cp -t` 의 차이는 문법이 아니라 프로그램 의미론이고, 그 표는
이미 틀려 있었다(실측: `cp -t`·`sed -i` 다중파일·`install -d`).

### 실측이 이 결정을 강제한다

실사용 589개 중 바닥값 경로를 **글자로 담은** 명령은 208건이다. 그런데 그 208건은
거의 전부 **래퍼 실행**이다:

    .claude/harness/bin/harness status
    .claude/harness/bin/harness advance
    .claude/harness/bin/harness help | grep …

바닥값을 진짜 **바꾸려는** 명령은 실사용에 **한 건도 없다.**

| | |
| --- | --- |
| 잘못 막을 기회 | 208건 (매 회차 래퍼를 부르므로 계속 생긴다) |
| 막아야 할 기회 | **0건** |

이 영역에서 제한을 조금이라도 넓게 잡으면 **틀릴 확률이 사실상 100%** 다. 맞을
대상이 데이터에 없다.

## 판단 기준: 잘못 막은 대가를 내가 받는다고 놓는다

지금까지 설계가 계속 과잉 제한으로 기운 이유가 있다 — **틀린 제한의 비용이
설계자에게 보이지 않는다.** 잘못 막으면 사용자가 승인 클릭·우회·시간을 내고,
설계자에게는 아무 신호가 없다. 그래서 "혹시 모르니 막아 두자" 가 공짜처럼 보인다.

기준을 뒤집는다.

> **잘못 막았을 때의 페널티를 설계자가 받는다고 놓고 판정을 정한다.**

그러면 확신 없는 자리는 자동으로 **포기**가 된다. 위 셋째 줄이 그 결과다.

## 포기 목록 — 명시한다

이 설계를 택하면 **다음이 통과한다.** 나중에 "왜 안 잡히지"로 되살리지 않도록
테스트에 단정으로 박는다.

| 통과하게 되는 것 | 왜 포기하나 |
| --- | --- |
| `cp evil "$D/x"` (D 를 모름) | 값이 실행 시점에 정해진다. 좁힐 여지 없음 |
| `python3 -c "open('.claude/harness/harness.db','w')"` | 인라인 코드의 **의미**는 문법 밖이다 |
| `find . -name harness.db -delete` | 대상이 실행 결과 안에 있다 |
| `'.claude/harn'+'ess'` 조립 | 리터럴이 아니다 |
| `cp evil .claude/harness/bin/harness` | 어느 인자가 대상인지 문법이 모른다 |
| `tee .claude/harness/harness.db < x` | 〃 |

앞의 셋은 지금 `ask` 를 낸다. 이 설계는 `bash_opaque` 와 `floor_named` 의
비-리터럴 경로를 함께 걷어낸다.

**둘째가 가장 크다** — 5회차 적대적 리뷰가 찾은 우회다. 다만 그것도 `ask` 였고,
bypass 모드에서는 자동 승인이었다. 막은 적이 없다.

## 남는 것 — 경계

    rm .claude/harness/bin/harness                → deny
    sed -i s/a/b/ .claude/harness/harness.db      → deny
    cat x > .claude/harness/bin/harness           → deny  (리다이렉트 = 문법 증명)
    SP=.claude/harness; rm "$SP/bin/harness"      → deny  (상수 전파)
    printf x >| .claude/harness/harness.db        → deny

오탐이 **구조적으로 불가능해진다** — 모르는 것은 아예 판정하지 않는다.

## 지워질 것

새 분할기가 서면 **우회로 붙였던 것들이 필요 없어진다.** 지운다:

- `DANGLING_BS_RE` — `\;` 로 깨진 조각을 되붙이던 것
- `strip_quoted_heredocs` 의 **판정용** 호출 — 본문이 애초에 한 낱말이 된다
- `bash_unresolved` 잔여(`parse-fail`) — 제대로 쪼개면 진짜 불균형만 남고,
  그때는 판정하지 않고 통과시킨다(포기 목록과 같은 원칙)
- `bash_opaque` — 위 포기 목록 셋째
- `floor_named` 의 비-리터럴 경로

남기는 것: `SELF_LOCK`·`floor_hit`·`rel_aliases`(symlink 별칭)·`sh_expand`(글롭).
이들은 **리터럴 경로에 대한 정확한 판정**이라 이 설계와 같은 편이다.

## 끝 조건

1. 실사용 589개 재생에서 **오탐 0** — 멈추는 것은 제어명령·승인 게이트뿐
2. 바닥값 단정 전원 통과 (기존 smoke 의 self-lock 절 전부)
3. 포기 목록 넷이 **통과한다**는 단정이 테스트에 있다
4. 변이 검증 — 분할기를 옛것으로 되돌리면 `parse-fail` 단정이 빨개진다
5. `tests/all.sh` 9/9, 의존성 추가 없음
6. `.dev/` 에 재생 스크립트를 남겨, 다음 회차에도 같은 589개로 잴 수 있게 한다

## 위험

판정 경로의 **기초**를 바꾼다. 889개 단정이 그 위에 있다.

- 완화 ①: 실사용 589개 재생을 **끝 조건에 넣는다.** 합성 코퍼스로는 이번 증상을
  못 찾았다 — 그 사실이 이 회차의 교훈이다
- 완화 ②: 변이 검증을 양방향으로 — 규칙을 되살려도, 없애도 빨개져야 한다
- 완화 ③: 한 번에 하지 않는다. 분할기 교체 → 재생·전체검사 → 판정 규칙 정리 →
  재생·전체검사. 각 단계에서 멈출 수 있다

## 하지 않는 것

- **AST 파서 의존성**(`bashlex`·`tree-sitter`). `shlex` 로 충분한 것을 확인했다.
  나중에 부족하면 그때 판단한다
- 상수 전파를 **명령 밖**으로 넓히는 것. 세션 상태를 추적하는 일이 된다
- 어느 인자를 쓰는지의 표. 이미 틀렸고, 바닥값에는 필요 없다
