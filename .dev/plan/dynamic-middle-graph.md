# 중간 그래프: 고정 틀 + 앞으로만 자라는 회차 한정 DAG (설계 합의, 2026-08-08)

stages.json DSL 의 다음 층. 사용자와 합의된 결정 사항의 기록이다.

## 목표

작업마다 다른 중간 절차(조사 중심·기계적 실행·검증 중심)를 그래프로 표현하되,
"너무 자유로운" 변경은 구조로 막는다. 동적 그래프 = 진행 중 **앞쪽에** 노드가 생기는 것.

## 결정 사항

1. **샌드위치 구조.** Selection → Scaffolding → [중간 그래프] → Compounding.
   틀 세 노드는 코드 고정 — `next` 선언 불가, 위치·불가침(스킵 불가) 유지.
2. **중간은 앞으로만 가는 DAG.** `next` 선언(생략 = 다음 항목, 기존 설치 완전 호환),
   분기 허용, 백엣지 금지 — 위상 검증기가 거부한다.
3. **뒤로 가지 않는다** (기존 결정 재확인, POLICY 4번). 되돌아갈 필요가 생기면
   회차를 빠르게 닫고(`skip until:compounding` → `advance --cycle`) 다음 회차로.
   따라서 재진입 증거 의미론·백엣지 리셋 정책은 **설계하지 않는다**.
4. **동적 추가는 회차 한정.** stages.json 은 안정된 기본 틀로 남는다. 진행 중
   노드 추가는 `harness path add <노드>` 류 CLI 로 DB 에 이번 회차에만 유효하게
   덧붙인다 — 회차가 닫히면 사라지고, 이력이 이벤트로 남는다.
   Planning 산출물이 "이번 회차의 실행 그래프"가 되고, 계획 승인 = 그래프 승인.
5. **방향 비대칭 게이트.** 노드 **추가는 자유** — 일을 늘리는 방향이라 어떤 게이트도
   사라지지 않는다. 미방문 노드의 **삭제·순서 변경은 스킵의 위장**이므로 기존 스킵
   동의 게이트를 그대로 적용한다. 새 규칙을 발명하지 않는다.

## 구현 골격

- 엔진: 단계 행 **지연 생성** (지금은 loop 생성 시 일괄 생성이라 나중에 추가된
  노드에서 `advance` 가 "다음 단계 행이 없다" 로 거절 — cli.py `_enter` 경로)
- `next` 해석: `advance` 가 분기 노드에서는 대상과 사유를 요구
- 위상 검증: `config_problems` 에 — 틀 노드 `next` 금지, 중간 전 노드가
  Scaffolding 에서 도달 가능하고 Compounding 에 도달, 백엣지 없음
- 표면: "N/M" 진행 표시의 분기 대응, skip `+N`/`until:` 의 경로 기준 재정의
- 회차 한정 노드: DB 스키마에 회차 스코프 노드 저장(스키마 변경 → 출시 시 init
  업그레이드 경로 안내 필요)

## 끝 조건 (합의됨)

1. `next` 선언 없는 기존 설정이 무변경 동작 — smoke·init_diff 통과
2. 중간 노드를 가감한 예시 그래프가 출시 인수 시나리오 한 바퀴 통과
3. 틀 고정·위상 검증이 `config_problems` 진단과 탐침에 잡힘
4. 회차 진행 중 `path add` 로 노드를 추가해 그 노드를 통과하는 시나리오가
   출시 검사에 포함됨

끝 조건 충족 = 완료. 리뷰를 돌린다면 이 변경분에 한정하고, 시작 전에 회차 수를
합의한다 (리뷰-수정 루프는 스스로 멈추지 않는다).
