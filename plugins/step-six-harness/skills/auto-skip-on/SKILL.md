# 스킵 자동 승인 켜기

```sh
.claude/harness/bin/harness auto-skip on --reason "왜 자동 승인으로 두는가" \
    [--uses N] [--scope loop|project]
```

이 명령을 실행하면 훅이 **사용자 승인 다이얼로그를 한 번** 띄운다. 승인 이후로는 개별
스킵에 다이얼로그가 뜨지 않는다.

## 범위를 좁혀라 (권장)

무제한으로 켜두는 것이 가장 위험하다. 켜둔 사실을 잊기 때문이다. 가능하면 만료 조건을 붙인다.

| 옵션 | 효과 |
| --- | --- |
| `--uses N` | 자동 승인 N회 후 만료. 실제 스킵이 일어날 때만 차감된다 |
| `--scope loop` | 현재 작업 루프 안에서만 유효. 루프가 바뀌면 만료 |
| (둘 다 생략) | 무제한 — `auto-skip off` 를 실행할 때까지 유지 |

둘을 함께 쓸 수도 있다: `--uses 3 --scope loop` 는 "이번 루프에서 최대 3회".

만료되면 `status` 가 이유까지 알려준다 — "사용 횟수를 모두 소진해 만료됐다" 또는
"루프 ... 범위였고 루프가 바뀌어 만료됐다". 사용자가 왜 게이트가 돌아왔는지 알 수 있어야 한다.

사용자가 범위를 지정하지 않았다면 **한 번 물어보라** — "이번 루프만으로 할까, 몇 회로 할까".
무제한이 정말 의도라면 그대로 진행한다.

## 왜 이 명령만 승인이 필요한가

자동 승인을 켜는 것은 동의 게이트 자체를 무력화하는 행위다. 이것까지 자유롭게 허용하면
모델이 스스로 켜서 모든 게이트를 통과할 수 있다. 그래서 **켜는 것은 사용자 승인이 필요하고,
끄는 것(`auto-skip off`)은 게이트 복원이므로 승인 없이 즉시 된다.**

`bypassPermissions` 모드에서는 다이얼로그가 뜨지 않아 켤 수 없다. 권한 모드를 낮춰야 한다.

## 켜져 있어도 유지되는 것

| | 자동 승인 ON |
| --- | --- |
| 스킵 시 다이얼로그 | ❌ 뜨지 않음 |
| `--reason` 필수 | ✅ 유지 — 사유 없는 스킵은 여전히 거부된다 |
| 기록 | ✅ `authorized_by=auto` 로 사람 승인과 **구분해서** 남는다 |
| 스킵 발생 시 사용자 통지 | ✅ `systemMessage` 로 매번 노출된다 |
| 다른 게이트(`allow`, `approve-plan`, `docs/` 차단) | ✅ 그대로 동의를 요구한다 |

즉 없어지는 것은 **다이얼로그뿐**이다. 사유와 감사 기록은 그대로다 — 그게 이 하네스의 본질이라
자동 승인이 그것까지 끄지는 않는다.

## 절차

1. 사유를 명확히 만들어 명령을 실행한다. 사유는 다이얼로그와 기록에 그대로 남는다.
2. 승인되면 상태를 확인시킨다: `.claude/harness/bin/harness auto-skip status`
3. `status` 와 세션 시작 컨텍스트에 `⚠ 스킵 자동 승인 ON` 이 계속 표시된다는 점을 알린다 —
   켜둔 사실을 잊지 않게 하는 장치다.
4. 작업이 끝나면 `/step-six-harness:auto-skip-off` 로 되돌리라고 권한다.
