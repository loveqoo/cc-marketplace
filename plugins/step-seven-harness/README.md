# step-seven-harness

**AI와 함께 일할 때 복리가 쌓이도록 작업 절차를 훅으로 강제하는 하네스입니다.**

`Selection` → `Scaffolding` → `Context` → `Planning` → `Execution` → `Verification` →
`Compounding` 일곱 단계를 순서대로 밟게 하고, 마지막 단계에서 **작업 종료**와
**다음 회차**로 갈라져 한 작업이 여러 회차를 돕니다.

[cc-marketplace](../../README.md) 의 플러그인입니다.

```bash
/plugin marketplace add loveqoo/cc-marketplace
/plugin install step-seven-harness@cc-marketplace
/reload-plugins
```

---

## 왜 만들었나

AI와 오래 일하면 같은 문제를 반복하게 됩니다. 지난주에 겪은 실패를 이번 주에 또 겪고,
계획 없이 코드를 고치다 되돌리고, 회고를 적어두지만 다음 작업에서 아무도 읽지 않습니다.
문서로 원칙을 세워도 **압축되면 잊히고, 급할 때 가장 먼저 무시됩니다.**

이 하네스는 그 원칙을 훅으로 옮깁니다. **훅은 잊지 않습니다.**

목표는 한 작업을 잘 끝내는 것이 아니라 **다음 작업이 더 쉬워지는 것**입니다. 그래서
마지막 단계 이름이 `Compounding`(복리)입니다.

## 누구에게 맞나

**맞습니다**

- AI와 여러 날에 걸쳐 같은 코드베이스를 다루는 분
- 회고를 적어두지만 다시 안 읽힌다는 느낌을 받아본 분
- 계획·검증 단계를 습관으로 만들고 싶은데 매번 잊는 분
- 사람이 자리를 비운 동안에도 작업이 굴러가길 바라는 분

**맞지 않습니다**

- 이미 그 절차가 몸에 붙어 있는 분 — 하네스는 대부분 오버헤드가 됩니다
- 한 번 쓰고 버릴 스크립트를 만드는 중인 분 — 쌓일 것이 없으면 복리도 없습니다
- 절차적 제약을 답답해하는 분 — 마찰이 커지면 결국 게이트를 끄게 됩니다

> **현재 상태를 솔직히 적어둡니다.** 테스트 375개와 두 차례의 적대적 코드 리뷰를
> 통과했지만, **실제 프로젝트에서 길게 돌려본 적은 아직 없습니다.** 낮은 위험
> 프로젝트에서 먼저 써보시는 것을 권합니다.

## 무엇을 하나

### 일곱 단계를 순서대로 밟게 합니다

단계는 **항상 앞으로만** 갑니다. 되돌아가는 대신 그 회차를 닫고 다음 회차를 시작합니다.

| 단계 | 하는 일 | 하네스가 막는 것 |
| --- | --- | --- |
| 0 `Selection` | 이번 작업과 **무엇이 '끝'인지**를 정합니다 | 둘 다 기록하지 않으면 다음 단계로 못 갑니다 |
| 1 `Scaffolding` | 구조를 확인하고, **쌓인 기록을 줄입니다** | 신규 최상위 폴더는 이 단계에서만 만들 수 있습니다 |
| 2 `Context` | 과거 기록에서 **이번 작업과 관련된 것만** 당겨옵니다 | — (권고) |
| 3 `Planning` | 계획을 파일로 남기고 사람의 승인을 받습니다 | 승인 없이는 소스를 못 고칩니다 |
| 4 `Execution` | 계획대로 실행합니다 | 단계별 쓰기 허용 경로를 벗어나면 막힙니다 |
| 5 `Verification` | 완료 조건을 하나씩 대조합니다 | 검증 증거 없이 턴을 끝낼 수 없습니다 |
| 6 `Compounding` | 세 질문에 답해 회고를 쓰고, **반복된 실수의 승격을 결정합니다** | 결정 없이는 회차를 닫을 수 없습니다 |

6번에서 두 갈래로 갈립니다. **작업이 끝났으면** 0번으로 돌아가 새 작업을 정하고,
**후속 회차가 남았으면** 1번으로 돌아가 같은 작업을 이어갑니다. 그래서 한 작업이
여러 회차를 돕니다.

### 복리를 만드는 장치가 셋 있습니다

| 장치 | 무슨 일이 벌어지나 |
| --- | --- |
| **실패 지점 주입** | 같은 명령이 두 번째로 실패하면, **그 자리에서** 몇 번째인지·이전 오류가 무엇이었는지·관련 회고 파일이 어디 있는지 알려줍니다. 마찰이 전혀 늘지 않습니다 |
| **승격 결정 강제** | 같은 실수가 여러 작업에서 반복되면 `Compounding` 에서 결정을 요구합니다 — 훅·구조·스킬로 **올리거나**, 사유와 함께 **보류**해야 합니다. 보류도 결정이라 기록되고, 그 항목이 또 걸리면 결정이 무효화되어 되돌아옵니다 |
| **회고를 찾아지게 씀** | 회고는 나중에 **명령 이름으로 텍스트 검색**되어 찾아집니다. 그래서 단계 진입 시 세 질문(무엇이 통했나 / 무엇을 잘못 가정했나 / 이 회차를 싸게 만들었을 것은)과 함께 **이 회차의 검색 키를 그대로 알려주고**, 회차를 닫을 때 그 키가 들어갔는지 확인해 알려줍니다. 막지는 않습니다 |
| **예산과 정리** | 승격된 규칙 문서(`LEARNED.md`)에는 줄 수 상한이 있고, `harness tidy` 가 정리 후보를 목록으로 줍니다. **쌓이면 복잡해지는 시스템은 복리가 아닙니다** |

그리고 `harness metrics` 가 **이게 실제로 효과가 있는지** 보여줍니다 — 승격 종류별
재발률, 마찰 추세, 그리고 그 짝인 **우회 추세**. 점수는 만들지 않습니다. 하나로 합치면
그 하나를 최적화하게 되기 때문입니다.

## 언제 끼어드나

하네스는 **스스로 일을 시작하지 않습니다.** 아래 순간에만 반응합니다. 그 외에는 조용합니다.

| 언제 | 무슨 일이 벌어지나 |
| --- | --- |
| 세션을 시작할 때 | 현재 작업·회차·단계와 그 단계에서 할 일이 주입됩니다 |
| 파일을 쓰려 할 때 | 그 단계에서 허용된 경로가 아니면 막고 **무엇을 하면 되는지** 알려줍니다 |
| 도구가 실패할 때 | **두 번째부터** 반복 횟수·이전 오류·관련 회고 파일을 그 자리에서 줍니다 |
| `advance` 로 단계를 넘길 때 | 종료 조건이 남았으면 거부하고 무엇이 남았는지 알려줍니다 |
| 턴을 끝내려 할 때 | 말머리가 없거나 검증 증거·회고가 없으면 막습니다. 조건을 다 채웠는데 단계가 남았으면 **이어서 진행하라고 되돌립니다** (최대 6회, 진전이 없으면 2회에서 멈춥니다) |
| 같은 실수가 **세 작업에서** 반복될 때 | `Compounding` 에서 승격 결정을 요구합니다 |
| 회차를 닫을 때 | 그 회차의 마찰 수치를 스냅샷으로 남깁니다 (`metrics` 의 원료입니다) |

### 사람의 승인이 필요한 순간

아래 다섯 가지는 **다이얼로그가 뜨고, 사유가 그대로 보입니다.** 모델이 스스로 승인할 수
없습니다.

| 명령 | 무엇을 하려는 것인가 |
| --- | --- |
| `skip <단계> --reason "..."` | 단계를 건너뛰겠다 (단, `Selection` 과 `Compounding` 은 불가) |
| `allow <경로> --reason "..."` | `docs/` 처럼 쓰기 금지 경로에 예외를 두겠다 |
| `approve-plan <파일>` | 이 계획으로 실행하겠다 |
| `loop new --reason "..."` | 작업을 닫고 새로 시작하겠다 (남은 단계를 건너뛰게 됩니다) |
| `auto-skip on --reason "..."` | 앞으로 스킵 다이얼로그를 끄겠다 (무인 실행용) |

무인 실행으로 `--dangerously-skip-permissions` 를 쓰시면 위 다이얼로그가 뜨지 않습니다 —
**사람이 세션 단위로 미리 승인한 것으로 취급합니다.** 사유는 여전히 필수이고, 우회 사실은
기록에 남아 `harness stats` 와 `metrics` 의 회피 열에 드러납니다. 예외는 `auto-skip on`
하나입니다 — 그 효과가 세션을 넘어 남으므로 사람의 판단을 받습니다.

> **승인을 면제해도 기록은 면제하지 않습니다.** 예를 들어 `Planning` 을 건너뛰더라도 계획
> 파일은 남겨야 합니다. 회차를 여러 번 돌 때 계획 10개가 남는 것과 스킵 기록 10개가 남는
> 것은 복리의 재료로서 완전히 다릅니다.

## 어떻게 시작하나

### 1. 설치합니다

위의 세 명령입니다. 마켓플레이스를 먼저 등록해야 플러그인이 보입니다.

### 2. 프로젝트에 적용합니다

Claude에게 이렇게 말하면 됩니다.

```
하네스 설치해줘
```

또는 직접: `/step-seven-harness:install`

`CLAUDE.md` 에 앵커 2줄이 추가되고 `.claude/harness/` 에 원칙·규칙·상태 파일이 생깁니다.
`git diff` 로 변경이 2줄인지 확인하실 수 있습니다.

### 3. ⚠️ 새 세션에서 시작합니다

**설치한 그 세션에서는 하네스가 반쪽만 동작합니다.** 원칙 문서(`POLICY.md`)는 세션 시작에
로드되는데 그 시점이 이미 지났기 때문입니다. `/reload-plugins` 로도 해결되지 않습니다.

**Claude를 새로 켜십시오.** 그러면 답변 말머리에 `[Selection]` 같은 현재 단계가 붙기
시작하고, 그게 하네스가 살아 있다는 신호입니다.

### 첫 회차는 이런 느낌입니다

```
[Selection] 이번 작업을 정하겠습니다.
  → harness loop intent "결제 모듈 리팩터링"
  → harness loop done-when "기존 테스트가 통과한다" "신규 API에 테스트가 있다"

[Planning] 계획을 .dev/plan/260805-a3f9c1-1-refactor.md 에 썼습니다. 승인해 주시겠습니까?
  → (승인 다이얼로그가 뜹니다)

[Execution] ... 어, npm test 가 실패했습니다.
  [harness] 'npm test' 실패가 2번째다. 이전 오류: ENOENT
            관련 기록: .dev/troubleshooting/260701-b2c4d1-1-npm-setup.md
  → 그 기록을 먼저 읽겠습니다.
```

## 무엇이 어디에 저장되나

| 경로 | 누가 쓰나 | 커밋하나 |
| --- | --- | --- |
| `CLAUDE.md` | 앵커 2줄만 추가 | ✅ |
| `.claude/harness/POLICY.md` | **사람이 정한 원칙.** 고쳐도 됩니다 | ✅ |
| `.claude/harness/stages.json` | **규칙의 단일 출처.** 마찰이 크면 여기서 덜어냅니다 | ✅ |
| `.claude/harness/LEARNED.md` | **하네스가 생성합니다.** 손으로 고치지 마십시오 | ✅ |
| `.claude/harness/rationale.md` | 왜 이렇게 통제하는지 상세 근거 | ✅ |
| `.claude/harness/harness.db` | 런타임 상태 (해시 발급 + 현재 단계) | ❌ 자동 gitignore |
| `.dev/` | 작업의 흔적 — 계획·회고·학습·트러블슈팅 | ✅ (복리의 원료입니다) |
| `docs/` | **사람의 영역.** 하네스가 쓰기를 막습니다 | ✅ |

`.dev/` 파일명은 `<작업해시>-<회차>-이름.md` 입니다. 앞단 해시로 `grep` 하면 한 작업의
산출물이 회차와 무관하게 한자리에 모입니다. `001, 002` 같은 증가 번호를 쓰지 않는 이유는
워크트리로 병행 작업할 때 서로를 볼 수 없어 충돌하기 때문입니다.

## 막혔을 때

하네스가 무언가를 막으면 **이유와 해야 할 일을 그대로 알려줍니다.** 순서대로 보십시오.

| 상황 | 대응 |
| --- | --- |
| 규칙이 맞다 | 하라는 것을 합니다. 예: 계획을 먼저 `.dev/plan/` 에 쓰고 승인을 받습니다 |
| 이 작업에 그 단계가 불필요하다 | `harness skip <단계> --reason "..."` — 사유가 사용자에게 그대로 보입니다 |
| **규칙 자체가 틀렸다** | 우회하지 말고 `.claude/harness/stages.json` 을 고칩니다 |

마지막 줄이 중요합니다. **무엇을 강제할지는 바꿀 수 있고, 강제하는 장치는 못 바꿉니다.**
`stages.json` 은 열려 있지만 엔진과 상태 DB는 잠겨 있습니다.

거추장스러운 규칙이 있으면 하네스를 끄지 마시고 그 규칙을 덜어내십시오.
`harness metrics` 의 **우회·스킵·보류 열이 오르는 것**이 그 신호입니다.

## 무엇을 보고 만들었나

복리 장치는 직관으로 만든 것이 아닙니다. 먼저 **다른 곳에서는 AI와 복리를 어떻게 올렸는지**
조사하고, 공통으로 나온 것만 골라 넣었습니다.

| 사례 | 무엇을 말하나 | 어느 장치가 됐나 |
| --- | --- | --- |
| [ExpeL](https://arxiv.org/abs/2308.10144) (2023) | 통찰 저장소를 투표로 관리하고 **중요도가 0이 되면 삭제**한다 | 승격 성숙도, 재발 시 결정 무효화 |
| [CODESKILL](https://arxiv.org/abs/2605.25430) (2026) | skill bank 가 add/merge/**drop** 으로 **크기가 수렴**한다. 그리고 **에러 메시지를 키로 그 순간 회수**하는 것이 작업 시작에 밀어넣기보다 효과가 컸다 | `LEARNED.md` 예산·`tidy`, 그리고 **실패 지점 주입** |
| [cass_memory_system](https://github.com/Dicklesworthstone/cass_memory_system) | 규칙에 성숙도와 반감기를 두고, **큐레이션에 LLM을 넣지 않는다** (자기 판단을 다시 판단하면 등급이 표류한다) | 성숙도를 **결정론적으로** 계산 — "같은 이벤트가 또 걸리는가"만 봄 |
| [Cursor Rules](https://techsy.io/en/blog/cursor-rules-guide) | 규칙의 **내용보다 발동 조건**이 레버다 | 실패한 순간에 주입. `recall` 을 pull 로 남긴 것은 의도적 절충입니다 |
| [AGENTS.md 설정 냄새](https://arxiv.org/abs/2606.15828) (레포 100개) | 가장 흔한 냄새가 **lint leakage 62%** — 훅으로 막을 수 있는 것을 산문으로 적어둔 것 | **승격 결정 강제**의 직접 근거 |
| [AGENTS.md Bloat](https://codex.danielvaughan.com/2026/03/27/agents-md-bloat-problem/) | 실수 → 규칙 한 줄 추가 → 또 실수 → 또 한 줄. 파일이 터지고 초반 지시가 묻힌다 | `Scaffolding` 을 "**줄이는**" 단계로 정의 |
| [State of AI Agent Memory 2026](https://mem0.ai/blog/state-of-ai-agent-memory-2026) | 에이전트 메모리 접근법 현황 | 배경 조사 |

**공통으로 나온 결론 셋**이 그대로 설계 원칙이 됐습니다.

1. **회수는 자동으로, 필요한 순간에.** 부르기로 마음먹어야 하는 저장소는 안 쓰입니다.
2. **저장소는 수렴해야 한다.** 쌓이기만 하면 마찰이 이득을 넘는 지점이 옵니다.
3. **기계화할 수 있으면 산문으로 적지 마라.** 62%가 걸린 함정입니다.

각 장치를 왜 그렇게 만들었고, **무엇을 측정할 수 없는지**까지
[`rationale.md`](templates/rationale.md) 에 적어두었습니다.

## 명령 한눈에

전부 외우실 필요는 없습니다. **막히면 훅이 실행할 명령을 그대로 알려줍니다.**

```bash
.claude/harness/bin/harness status     # 지금 어느 단계이고 무엇이 남았나
.claude/harness/bin/harness advance    # 다음 단계로
.claude/harness/bin/harness recall     # 이번 작업과 관련된 과거 기록
.claude/harness/bin/harness metrics    # 복리가 실제로 생기고 있나
.claude/harness/bin/harness help       # 전체 사용법
```

`status`·`metrics`·`tidy`·`promote` 는 `--json` 을 붙이면 구조를 그대로 냅니다.

## 하네스 자체를 고칠 때

이 플러그인의 코드를 수정하실 때 쓰는 검사 셋입니다.

```bash
sh tests/smoke.sh             # 매번 돌립니다 (문서 검사 포함)
python3 tests/math_check.py   # 측정 산술을 손계산과 대조
python3 tests/doc_check.py    # 문서의 산문 중복·깨진 링크
sh tests/init_diff.sh         # 설치 동작이 리팩터 전과 같은지 차등 실행
```

`smoke.sh` 는 출력을 파일로 받아 **종료 코드를 확인하십시오.** 파이프로 넘기면 종료 상태가
삼켜집니다. 그리고 새 검사를 넣을 때는 **일부러 깨뜨려 잡히는지** 확인하십시오 — 실패할 수
없는 검사를 세 번 만든 뒤 얻은 교훈입니다.

경로이므로 회고·계획 파일, 상태 DB, `LEARNED.md`, 승격 이력이 전부 그대로 쓰입니다.
